# 下注策略与版本

## 两个独立版本

概率模型控制比分/净胜球/让球概率的推导；下注策略控制准入、分池、结构、保护、购票排名、预算与发布结算流程。当前参考搭配：`probability_model_id = "FM-1.7.1"`、`betting_strategy_id = "BS-0.1.0"`、`betting_strategy_version = "0.1.0"`。报告和网页显示“概率模型FM-1.7.1｜下注策略BS-0.1.0”，不得用FM版本代替下注策略版本。

权威参数定义在仓库 `config/betting-strategies/BS-0.1.0.json`；本文件解释规则，不是第二份配置。JSON是策略定义，目前包入口不自动读取它，也不会自动消费新增版本字段；客户端必须读配置、显式传参并与产物policy/准确票单核对。不要编造不存在的“按策略版本自动生成”API。

新冻结的request、生成manifest、发布/验收收据及网页说明记录上述三个字段，另记录参数/配置SHA256。概率模型升级可保留下注策略号，前提下注规则未变且新模型准入契约重新验收；改变结构、排名、金额、场次准入、保护或重叠规则应产生新策略版本，或明确标为未发布变种。BS-0.1.0不意味着已验证盈利或具有最优覆盖。

## BS-0.1.0规则

- 每轮8个七场组，结构3332222、无单选；每组理论432组合。按原概率组合乘积降序（等价sum(log(p))）买第30–154名，含两端；125注×2元=250元/组，每轮1000注=2000元。0.65只在票级回款中使用一次。
- 显式北京时间窗口[start,end)，北单三项赛前SP完整、有限正值且最小值≥2，等于2允许；赛程/slot/身份/让球/SP/结果/正式结算SP均用Nowscore。不能拿欧赔筛选后的epoch作为纯北单准入池。缺数据与接口失败单列，不把失败当无赛事。
- 原生基本面不确定，仅当三路市场充分一致时保留并直接用市场网格，不把uncertain标签改成adequate。不足则排除；不是允许任意uncertain。FM-1.7.1同赛事历史支持、λ/ρ及尾部处理仍归模型契约，见same-competition-release.md。市场篮子、数量、时效、残差和受支持总进球线门槛见JSON；当前总进球线低于2.5的复核限制必须披露，不能说这些比赛本身不可靠。
- 不按开赛时间段硬切轮次。按Top1−Top3升序、fixture_id固定并列键排序，再轮流分配到不同池；目标约20场/池，自动轮数ceil(合格场数/20)，轮间候选池不重叠。20是目标，不是每轮必须20场；每轮仍须独立凑齐8组。所有池需同截止及同概率基座。
- 每个七场底组，Top3严格>20%的候选中，按Top2−Top3差最小取3场三选；余4场双选。底组按四场常规双选覆盖概率之积排序，再按fixture键；在共享/复用限制下贪心选择8个不同底组。这是现有启发式，不宣称全局最优。
- 保护复用BuildJointProtectionPlan选出的8个Top1+Top2／Top1+Top3掩码，再按原顺序应用到不同底组。不能写成“每组双选都选Top1+Top2”，也不能宣称跨底组仍完整保护所有两场/三场Top3组合。详细实现复用BuildDiversifiedProtectionPlan，不在技能重写掩码算法。
- 任意两组最多共同6场，三选也计入；同决策包每场最多被8组选中，不能拼接不同cutoff的复用账本。实际七场赛果票不得重复，生成器报告重复不等于自动去重：发现重复则发布验收不通过，不静默删票或缩深度。
- 规划阶段距冻结至少15分钟；发布前再次确认所有实际购票场次尚未开赛。候选/预算不足不得擅自改门槛、减深度、加单选或放宽重用。多轮总资金为2000×实际可行轮数，先报告规模，在用户授权总范围内发布。

权威调用依次为PrepareMixedRoundInputs、PartitionMixedRoundFixtures、BuildMixedRoundPlans、ValidateMixedRoundPlans（见mixed-round-replay.md）。显式传入start_rank=30L、end_rank=154L、n_groups=8L、core_sp_threshold=2、triple_min_top3=.20、max_overlap=6L、max_reuse=8L、unit_cny=2、payout_factor=.65及准确总预算。输入预先执行三项SP最小值≥2，core_sp_threshold=2只是包内Top1 SP额外门槛，不能替代三项最小值筛选。内部选组预算2048/256元仅用于选组阶段，最终购票金额是2000/250元，不能混为支出。

## 发布与复现

执行operations.md的“新轮次发布步骤”。复现时用原冻结输入与原cutoff，不重新采集、不把后来赛果传入选票，不用新model替换旧model。参考实现为 `results/fm171-check-20261019/` 的prepare/market/freeze/plan/render/check-plans/activate等命令客户端，以及 `quarto/fm171_publication_20261019.qmd`；它们是固定一期实例，不能原样执行当通用新一期生成器，包与共享更新器才是权威实现。

BS-0.1.0在10/19参考单发布后定义。可通过新版本标注收据，将其已冻结参数核验为该版本，并在面板显示两个版本；不能覆盖原request/manifest/概率/票单哈希或声称版本标签在原截止前已冻结。旧历史轮次没有明确策略版本的保留“未标注”，不因参数看似相近就批量追认。历史人工延期SP=1结算同样保留人工口径说明，不能当未来统一延期规则。
