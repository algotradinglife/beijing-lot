# Beidan strategy

在 beijing-lot 仓库中执行。先读取仓库 AGENTS.md、现有配置和本次用户要求。复用 R package 与现有研究客户端，不在技能里实现概率、排序或结算算法。此技能生成研究用模拟单，不执行真实付款或购彩。

## 任务边界与参数

先识别本次要求是基本面分析、历史回测/诊断、检查场次、生成单、发布网页，还是更新结算；执行用户要求的范围。生成并发布下注单默认包含登记小时赛果和收益结算更新，除非用户明确要求仅冻结或不自动更新；无需重复确认。单纯检查场次不改票单或服务。缺少关键时间窗口或预算时用简短问题补齐，同时继续独立的数据核验。

将选择记录为显式参数：期号、时区、开赛窗口[start,end)、决策截止UTC、基座及每基座组数、预算CNY、每注金额、七场结构、组合排名区间/排序基准、Top1 SP门槛、三选规则、场次复用/组间共享上限、重复物理票处理、更新周期、网页地址。相对窗口绑定一个保存的参考时刻，不能随采集时间漂移。排名含两端：150–300是151注，每组302元，8组2416元；150–324是175注，每组350元，8组2800元。用户说“场”但实际上可能指“组”，依上下文判断，有实质歧义再澄清。

最新讨论常用3332222、原生概率排序150–324、Top1 SP≥1.9、Top3>20%且Top2−Top3差距小优先三选、组间最多共享6场、无总复用上限；这些是可覆盖的会话选择，不是所有后续任务的强制默认。不要把特定一期的7北单＋1xG-DC配置当成永久分配。预算不足不静默缩深度，候选不足不擅自降门槛或换基座；明确缺口和未用资金。

## 基本面概率与历史回测

单场或有界批次的预测报告，按 [预测报告契约](references/prediction-report.md) 输出让球胜平负及比分概率，整合各维度证据、盘口水平与变化，并解释最终判断。报告本身不要求预算或串关结构。

完整流程当前版本 **FM-1.5.0**（冻结对照FM-1.4.0）。原生λ由长期主客场攻防与近期状态共同估计，默认近期混合权重alpha=0.5；对手强度、阵容和伤停有证据时评估其贡献及重复信息，不把近期状态留到尾部阶段。当前可执行的最小实现及局限见[基本面流程](references/fundamental-probability.md)。市场只补充/复核，不自动以联合市场反解替换原生λ；没有新增依据可保持λ并记录分歧。

尾部统一采用[中心等距规则](references/scenario-tail-adjustment.md)：冻结唯一最高概率净胜球单档为中心，逐层成对扩展；任一侧达到10%（含等号）则两侧都纳入，两侧均低于10%则停止，核心半径最多2。核心权重1，外围0.3，完整归一化。并列中心或审查未定保留原网格；强弱/均衡是解释背景，不再选择不同尾部算法。旧TAILR与固定Top3分支仅保留为冻结历史证据，不用于当前版本。

流程：明确截止 → 原生基本面λ及DC网格 → 同截止欧赔/大小球/亚盘独立比较与有证据的接受/拒绝账本 → 冻结校正前分布与审查 → 中心等距核心/外围 → 完整比分重加权并冻结 → 投影实际北单让球 → 按完整类别概率排名Top1/Top2/Top3。北单线与期望角色不能参与λ或核心校正；单档众数不代替类别排序。实战参考提前24小时或实际提交时间，15分钟仅历史漂移诊断。ρ显式传入，手工−0.1不是校准常数。记录三类差距、边界核心敏感性及三选依据；不增加未经批准的选项阈值。

复用 `adjust_score_margin_distribution()` 执行明确的净胜球分档目标；不根据角色自动拍概率、不返拟合λ/ρ、不为了排序而静默挪质量。投影排序与预想冲突必须披露，不能据此返调比分。保留数据基准、市场复核、方向校正三份视图，旧FM-1.2阶段仅作历史对照。当前快照适配仍仅授权历史诊断，新增流程不等于生产前瞻准入。

整期历史基础估算与复盘使用 `EstimateFundamentalIssue()` / `ReviewFundamentalIssue()`，细节见同一函数契约。固定全期名单、事实版本和单独赛果快照；每场提供显式截止，估算失败也保留。该批量入口目前只生成基础阶段，未评估的定性/盘口阶段不伪造为综合预测；日粒度比分代理及未确认90分钟口径限制如实报告。

历史重放、模型比较、命中/收益/回撤归因，读取 [诊断方法学](references/diagnostic-methodology.md)，按问题查 [函数与数据契约](references/diagnostic-functions.md) 及实际源码、测试。基本面回测在相同场次比较主选命中、Top2覆盖、保护项增量覆盖及方向稳定性，同时报告 Brier、log loss、校准、支持数及排除；只有复用真实票单或完成同预算完整策略重放时才评价策略收益。定性账本须在打开目标标签前冻结；已经看过目标赛果的手工复盘单列为事后诊断，不能当作独立回测证据。

先定义可证伪假设，再从数据、概率、候选、选组、覆盖深度和结算逐层作必要对照。普通诊断不自动采集、重训、发布、登记更新或改写冻结账本。历史代理与真实可用性证据分别报告；将诊断结论转为参数、阈值、权重或路由规则时，必须使用仓库 AGENTS.md 规定的共享 temporal_learning 上下文、显式截止、收据和独立重放，禁止复用旧客户端中的时序实现。

新增可复用 R/Python 实现分别放入 packages/beidan/R/ 与 packages/beidan/inst/python/beidan_backend/；r/、src/ 仅保留研究客户端。现有诊断索引中的旧期接口属于版本化证据，调用前核对当前源码与测试；索引不是前瞻准入证明。仓库 skills/beidan-strategy/ 为技能唯一维护源，用户安装副本同步整个目录。

## 平台研究扩展

需要赛程变更、xG字段核验、阵容/伤停背景、赔率轨迹、实时进度或赛后过程解释时，读取 [V球研究用途与口径](references/vfootball-research.md)。该文档将平台12类提示词映射到本技能用途，区分模块覆盖探测、球员可用性与不同阶段xG。窗口检查、生成新单、实时跟踪和赛后复盘按任务组合使用大部分模块，逐层汇总背景与证据；新增背景不自动修改已验收概率、分类、排名或冻结票单。

## 检查与生成

读取 [概率与场次](references/probabilities.md) 检查平台覆盖、匹配、赛前输入和逐层排除台账。每个基座使用自己的准入池、分类和排序，不强制共同池。纯北单不得先被欧赔/xG可用性筛掉。

混合分池、重分组或复现已有混合轮次时，读取 [混合分池与冻结复现](references/mixed-round-replay.md)，调用包公开入口，逐项核对原池、组与完整票序。混合场次不等于混合概率；复现默认离线，不重新采集或发布。

读取 [构造与冻结](references/planning.md) 生成准确票单。采集、验证、选组、枚举、排名、冻结与后续标签观察分开。对手ρ无法输出或只有历史时钟代理时，报告不可用/诊断限定，不能冒充已满足前瞻要求。目标结算不能参与任何选场、阈值、保护掩码或排名选择。

## 网页与更新

生成或发布网页、设置小时更新时读取 [发布与结算](references/operations.md)。使用包模板生成可远程查看的准确组合及CSV；冻结票单作为结算唯一购票依据，更新时不重新选票。发布、登记、配置、验收记录在锁和回滚事务内处理，保留旧轮次、未完成轮次及备份。

比分确认与结算SP确认分开：可先更新命中，收益仍待结算。即使全部票已死也继续查询购票场次，直到所购比赛结果与结算统计完整。全完成后停止网络查询，不把未发布SP当0元。

## 验收与回复

每次交付有执行启用的QMD，声明输入/来源时间、参数、哈希、截止与排除、本次模式的结果、限制及复现命令；预测报告展示概率与证据，生成票单时另展示准确票单和预算。按AGENTS运行相关函数测试、干净进程QMD渲染和codex review，记录审查文件哈希、发现与修复；未运行项明确说明。使用已安装的beidan验证Rcpp可加载，不能把load_all缺失DLL误判为算法失败。不参加CI，除非用户明确要求。

发布后核验远程HTTP、表格、链接、冻结排名及本地字节，核验服务/timer真实启用、单次更新成功和下一次触发时间。交付简报包含各基座候选数/排除原因，组数、实购注数、投入/余额，网页链接，命中与收益状态，以及自动更新终止条件。历史回测单独标识，不改写原冻结模拟单账本。仅用于数据研究，不构成投注、购彩或投资建议。
