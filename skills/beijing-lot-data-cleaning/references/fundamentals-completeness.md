# 基本面分项验收

- 以完整期次名单为分母，核验比赛及双方原生ID、双方近期战绩、交锋、适用积分、赛事/阶段、主客与中立标记、计划时间。盘口另列欧赔、大小球、亚盘及目标赛前时点覆盖，不能由基本面验收推定盘口齐全。
- 每个场次×维度区分：有记录、来源明确为空、不适用、采集失败、解析失败、冲突未决、字段未知。空结果须有正文和解析回放证据；不等于历史上从未发生。分项计数须与整期名单对账。
- 积分按赛事类型检查联赛表或杯赛小组表；友谊赛不适用，淘汰赛可无当前阶段小组表，不能补零或默认缺采。保留判断依据。
- 分别报告采集覆盖、内容口径和赛前可用性。历史比分未确认90分钟口径、历史中立场未知、两源历史范围差异应单列；两源一致不代表独立验证。定性战意审查未做完不能被称为数据齐全的一部分。
- 后采页面标注历史代理，不能因补全成功便准入历史赛前模型。逐来源保留URL、正文哈希、采集时间及字段选择依据；导出再读回核对时间精度、空值与类型。汇总分别计算未知和显式值，核对分项之和，避免同名汇总变量覆盖原列。
- 时间裁决区分计划和实际开球。仅采用证据支持的精度，保留两源原值、授权范围及有效值；单场授权不升级为全局来源优先规则。原cutoff不在输入中时明确“未提供”，不能猜测或清空冻结cutoff。
- 裁决归档后核查实际消费者读取的有效字段、版本及哈希。JSON裁决或有效CSV已生成，不等于标准Parquet及模型已采用。分别报告“证据归档”“有效层生成”“下游采用”；未验证的阶段保持未完成，不因此自动重跑模型或改写冻结结果。

例：26098:135按用户授权采用官方日历的计划时间；这是单场裁决，不能推导实际开球已核实。具体证据保留在项目异常台账和版本归档，技能不保存当前批次指标。
