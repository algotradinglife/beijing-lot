# 北单历史数据清理

本 skill 保存用户在数据清理会话中确认的规则。任务开始时读取工作仓库的 AGENTS.md；涉及规划、路由或验收状态时读取实时 GitHub Issue Graph。用户的新指示优先；历史笔记不能覆盖实时图状态。

## 工作入口

1. 确认当前仓库、任务范围、输入 manifest、原始缓存及已有裁决。不要把文件名版本号最大视作已验收版本；查阅 `docs/research/fundamentals-data-quality-register.md` 最新裁决及对应验收证据，并验证 manifest 哈希。
2. 根据清理对象读取 [清理规则](references/cleaning-rules.md)；修改或重跑前读取 [实现与验收入口](references/implementation.md)，优先复用现有函数。
3. 采集、解析、核验、裁决和派生输出分开。盘口原始正文适用 2026-09-18 用户批准的 SQLite 每 50 期迁移验收后清退规则（见数据存储 skill）；异常字段和值、来源 URL、哈希、采集及解析身份、核对依据和结论必须保留，不能只保留异常标签。其他数据仍保留原始响应。先采集清单中两源页面，再离线核对。同场身份必须成立，不能通过替换日期掩盖错 ID、主客颠倒或改期。
4. Titan 为主源，Nowscore 交叉核对和补缺。使用 Nowscore 替换错误数据时，要与 500 或澳客核对；其他独立历史报道可作为佐证，明确证据及其支持的字段。已有批准规则可直接执行。用户已授权自主形成有证据的建议、裁决、更新规则并推进清洗验收；证据不足或仍冲突的记录保持隔离并继续独立核验，不把推断记成已证实事实。
5. 更新跨期异常总表；待裁决内容先在对话展示。裁决之后才在 QMD 展示如何整合、更新有效数据。实际修正使用可重放的裁决层，不能覆盖原始来源。

盘口批次按完整遍历和可核验凭证准入，不要求整期 HTTP 全成功；失败页面逐项登记补采。见清理规则中的“盘口整期清洗准入”。

## 整期基本面完备度

逐场、逐维度冻结验收清单；先声明本轮必备范围，伤停和阵容是否必备由任务约定决定。整期补全与完备度询问按[分项验收规则](references/fundamentals-completeness.md)执行，不以网页抓取成功或总行数代替验收。

## 裁决与交付

对话表格按需包含：期/场次、比赛及 ID、原期状态、Titan 信息、Nowscore 信息、500/澳客/独立证据、调整建议、依据与不确定性。缺失、抓取失败、解析失败、错误和建模条件不足分别记录；不要把覆盖率问题都当作事实错误。

修正记录至少绑定：裁决 ID、精确行键、原值/新值、用户授权或已批准规则、来源 URL/本地证据及哈希、原 cutoff、实现身份、生成时间。重建时保留先前裁决及来源元数据，验证重复执行和未涉及场次不变。

交付以 QMD 为入口，复用 r/ 与 src/ 函数。展示按场次的来源 tibble（Titan、Nowscore 分表，列名尽量对齐）、结构、前几行、修正前后及排除原因；无需额外 RDS。完成相关自动测试、干净进程执行渲染与 Codex review，再报告验收结果。数据准备更新不等于模型或收益已重跑。

## 持续维护

用户新增或修订规则时更新此 skill 的对应段落，注明适用范围；被替代规则不再作为执行入口。具体场次证据保留在仓库异常台账，不复制全部历史进 skill。数值窗口属于显式实现政策，不擅自提升为适用于所有数据源的事实。

本 skill 不自行扩大采集范围、修改结算库、推送代码或重新训练模型。执行这些任务以当前授权为准。数据采集与补缺优先读取并使用 agent-reach 技能，选择目标网站已有后端及有界重试链；结果仍进入项目解析、核验和权威存储流程，保留失败与重试记录。
