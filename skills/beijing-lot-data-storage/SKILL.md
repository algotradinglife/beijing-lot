# 持久化存储

以当前工作仓库 `config/persistent_data_layout.json` 为机器可读目录契约，
`docs/operations/persistent_data_layout.md` 为操作说明；不要在 skill 复制目录表或当前批次编号。
仓库中的 `skills/beijing-lot-data-storage/SKILL.md` 是本 skill 的维护源；更新后同步到本机发现目录。

## 开始与收尾

1. 定位当前仓库并读取 AGENTS.md。已授权的数据采集、清洗、验证和批次发布适用数据流水线例外，不以读取 GitHub 为前置条件；依据本地已验证凭证和互斥锁推进。GitHub 不可用时记录待同步事项；改变范围、图关系或 Issue/Project 状态仍须实时图。
2. 使用项目 Python 执行：
   ```sh
   "$project_python" scripts/check_persistent_data_layout.py --contract config/persistent_data_layout.json
   ```
   其中 `project_python` 是当前仓库配置的解释器绝对路径；从仓库根目录运行。
   非零退出时，先查明挂载、缺目录或引用漂移；不要自动创建替代数据根、重新采集或切换版本。
3. 从 `registry/*-current.json` 读取当前已登记版本，向函数显式传入路径。尚未有当前引用的数据族使用明确的 manifest；不取“最新目录”，不回退工作区数据。
4. 数据写入前核对输出位于契约规定的对应域。源码放 r/src/scripts/quarto；按下述盘口保留例外处理原始正文，其他数据仍保留原始字节；修正与派生输出分开，发布版本不覆盖。
5. 完成后重跑检查；变更函数跑对应测试，QMD 在干净进程渲染，完成 Codex review。路径检查 PASS 只证明列明的路径约束，不证明数据内容、完整覆盖、哈希或历史准入。

## 归档、迁移与运行服务

先读上述操作说明及目标脚本的 `--help`，复用：
- `scripts/stage_market_persistent_inputs.py`：准备并核验盘口输入。
- `scripts/finalize_market_storage_cutover.py`：停写窗口内锁定并迁移请求账本和新增响应。
- `scripts/retire_archived_workspace_data.py`：归档哈希、成员清单和原字节核对后清退已登记源副本。
- `src/data_archive.py::read_archive_members`：哈希核验后离线读取冻结归档。

不重新手写复制/删除流程。迁移活跃 SQLite 先使用已有一致性备份或停写流程；
不得直接复制正在变化的数据库。先切换消费者和定时任务并验证新写入，再清退旧源。
保留原 manifest 中的历史路径作为证据，用映射清单定位归档成员，不改写历史来源。
非盘口迁库清退范围的冻结小文件可采用现有 tar.zst 归档，避免 exFAT 小文件空间放大。

## 盘口 SQLite 与原始正文清退（2026-09-18 用户授权）

盘口采集数据按每 50 期迁入持久化 SQLite；不要求恢复当时页面，验收后允许删除原始 HTML、JS、响应 JSON 或仅含已迁入内容的归档。此规则取代盘口范围内长期保留原始响应正文的旧要求，不适用于结算或基本面正文。

完整保存已提取报价序列、原始顺序及来源字段，长期保留原始 URL、比赛/期次/场次标识、采集时间、原始哈希、解析器身份和异常核对台账。异常须有具体字段和值、来源差异、依据、处理状态及结论；抓取/解析失败也要保留来源和失败原因，不得标记为正常空数据。未知或未提取字段不能冒称已保留。

每批须完成事务入库、幂等及回滚测试、记录级核对、独立数据库备份、读取消费者切换、QMD 报告和 Codex review，再清退该批原始正文。删除须有精确文件清单和可恢复的清退日志；共享页面须确认其他期次的读取引用也已迁入，不按目录或日期一刀切。保留小型采集凭证、异常与迁移记录；不重置采集预算/断点，也不把存储迁移当作新的内容清洗验收。

来源完整性不仅检查现存记录的哈希，还须冻结并核验完整成员清单（报价、重试、异常和解析证据的记录标识及哈希）。清单在原始来源回放、独立备份逐记录比较后生成，绑定验收凭证；普通读取和跨期复用均检查缺失或新增成员。不得从残缺数据库重建清单来消除校验失败。仍依赖原始文件的裁决重放须加入保护引用清单，直到该消费者也已切换并通过测试。

盘口迁库时读取 `docs/operations/market_sqlite_migration.md` 的批次续跑与两阶段验收说明。
复用 `scripts/prepare_market_sqlite_batch.py` 顺序准备指定批次；先提供明确覆盖该批的异常台账保留计划。
该入口不选择下一批、不授权删除。冻结实现变化后不能冒用原批次身份续跑；先核实旧事务及进程状态，再保留失败凭证并冻结新身份。
独立核对文本属于异常证据，保留正文、链接和原始哈希，不当作报价响应 JSON；归档来源按注册表凭证解析，不能根据文件缺失跳过。
清退完成后分别验证文件实际缺失、冻结来源清单和清退 QMD；日志一致不能替代数据库与文件核验。

新增定时入口必须在执行写入前调用目录检查；部署后核对安装配置与仓库配置一致。
不得仅因路径调整重置请求预算、采集断点或当前批准的请求间隔；现行配置以运行服务和登记表为准。
收集/清洗完成与存储迁移完成分开报告。变更目录约定时同时修改契约、相关入口、测试和文档，检查通过后部署。
