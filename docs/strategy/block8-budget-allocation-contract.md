Owner requested planning then DSH implementation, Codex review and updating the original quarto/26098_walkthrough.qmd. This is an engineering baseline, not completion of blocked research #495–#498 or evidence of optimal returns.

## Public stages

All outputs are tibbles or named lists of validated tibbles. No scraping, persistence or historical fitting occurs. All decision-facing stages receive explicit projected$cutoff; reuse authoritative chronology/identity/status helpers. Match count is settings$n_legs, equal across all groups, never fixed at7. No n_groups purchase target.

1. `parlay_budget_state(settings, prior_purchases, cutoff, spend_limit_cny = NULL)` returns a one-row tibble(issue_id, issue_budget_cny, spent_before_cny, remaining_cny, available_cny, affordable_units, unit_cny). Reuse prior-state/binding validation. Issue cap is1024 from explicit settings, unit2. Prior history must include fixture_sets and chronological/issue bindings. An optional current-decision spending cap cannot raise the issue balance. Round down to whole units; never spend negative balance; report invalid overspending instead of hiding it.
2. `parlay_generate_candidates(projected, settings, construction_policy)` returns group_legs plus search diagnostics. Explicit policy supplies max_candidates and seed, no purchased group count. Eligible fixture sets may overlap; canonical identities deduplicate sets. Use exhaustive combinations when count<=max_candidates; otherwise bounded deterministic seeded candidate sampling, report theoretical count, examined count, incomplete search. Use mature base R combinatorics/sampling, preserve RNG state. This initial search is a bounded baseline, not global optimality; structure assignment reuses entropy_desc. Return typed empty for fewer than n_legs eligible fixtures. Ensure projected cutoff/status validation is reused.
3. `parlay_coverage_frontier(projected, group_legs, patterns, settings, policy)` reuses structure masks, ticket enumeration, values and ranking. Returns candidates/supports, tickets/ticket_legs/candidate_tickets, ranked, and a frontier tibble(candidate_id, group_id, depth, cost_cny, cumulative_probability, marginal_probability, cumulative_ev_net). One curve per candidate, includes depth0, depths cannot exceed budget units/legal support. Probability is UNCONDITIONAL original product mass, not normalized within a mask. Apply explicit min_support_mass (default0, uncalibrated) and report rejected candidates. EV remainsNA when SP unavailable. No historical labels. Keep legal masks distinct from truncated purchases.
4. `parlay_allocate_portfolio(frontier_result, group_legs, budget_state, prior_purchases, cutoff, constraints, objective)` returns purchases, selected-group/candidate allocation summary, updated history and diagnostics with derived n_groups, units/cost/unspent and selection reason/trace. Constraints: max_reuse and max_overlap include prior purchased groups. Count reuse by distinct funded groups, not tickets. One structure per selected group; physical ticket ID cannot be purchased twice across candidates/history. Additional tickets in existing group do not consume another group reuse slot. Compare the next unique ticket in each admissible candidate by marginal objective per CNY; opening a group and deepening an admitted group compete in the same loop. Deterministic ties. Probability objective is expected NUMBER of winning tickets (sum of marginals), NOT probability of at least one win or profit; overlapping group events cannot be summed as a union. EV objective requires all evaluated tickets to have real valid predecision SP, use existing transform>10=>4.5 and one0.65 ticket factor; fail clearly on missing SP, never silently switch objectives. Leave nonpositive marginal objective unspent in both modes. Document greedy approximate nature and do not claim global optimum. Zero affordable units or no feasible tickets produces typed empty outputs.
5. `parlay_plan_summary(result)` returns human-readable group summary and ticket selections: group display label, canonical group_id, fixtures, structure, purchased depth, legal support size, cumulative coverage, cost, objective and EV availability. Canonical IDs remain stable internal keys; display labels are not identities. Clearly distinguish per-group coverage from portfolio union probability.
