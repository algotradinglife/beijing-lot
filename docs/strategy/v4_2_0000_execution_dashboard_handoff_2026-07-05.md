# v4.2.0000 Execution Dashboard Handoff

Date: 2026-07-05

## Scope

Strategy publishes v4.2.0000 execution artifacts as structured shadow CSVs.
Dashboard consumes the declared artifact and renders the fields. Dashboard does
not recompute recommendations, execution codes, full-cover caps, late-refresh
state, or N.

## Variants

Use decision-chain version ids in the new `x.y.abcd` format:

```text
shadow_v4.2.0000_execution_strict_fullcap2
shadow_v4.2.0000_execution_late_proxy_fullcap2
```

- `strict_fullcap2`: pre-refresh state. Rows requiring late refresh are no-buy.
- `late_proxy_fullcap2`: executable state after a valid late SP refresh.

## Required Dashboard Behavior

Issue Board / Match Detail:

- show `shadow_selection_codes` as the executable selection;
- show `execution_recommended_codes` as the audit recommendation;
- show a difference marker when recommended and executable differ;
- show `execution_action`, `execution_reasons`, `execution_full_score`,
  `execution_full_candidate`, `execution_full_kept`, and
  `execution_segment_idx`;
- use `execution_unlock_state` for late-refresh stop color:
  `waiting_late_refresh` is red, `unlocked_after_late_refresh` is green;
- show `shadow_stop_flag=1` rows as no-buy/wait/skip, not as executable picks.
- render `skip_wait_late_refresh` as a temporary stop/wait warning. The user
  should understand that this match is not safe to bet before a valid late SP
  refresh, even if audit recommendation codes are present.
- keep the selected execution policy visible when data auto-refreshes, so a
  change from strict/wait to late-proxy/executable is not silent.

Rolling/N views:

- use only `shadow_selection_codes`;
- ignore `execution_recommended_codes` for ticket generation;
- do not recompute N from execution fields.

API / manifest:

- expose the variants only when declared by active release manifest;
- suppress undeclared `shadow_arm` artifacts;
- treat `execution_*` fields as read-only artifact columns.
- when both strict and late-proxy artifacts are available for the same version,
  API should select the late-proxy artifact by default. This is the automated
  stop-unlock signal.

## Automated Stop Unlock

Stop unlock is automated at the artifact/API layer:

1. Before a valid late SP refresh, strategy publishes/selects
   `strict_fullcap2`; late-refresh rows have
   `execution_unlock_state=waiting_late_refresh` and should render red.
2. After a valid late SP refresh, strategy publishes
   `late_proxy_fullcap2`; rows previously held by the late-refresh gate have
   `execution_unlock_state=unlocked_after_late_refresh` and should render
   green.
3. API defaults to `late_proxy_fullcap2` once that artifact is available, while
   keeping `strict_fullcap2` selectable for audit.
4. This unlocks the row as an executable recommendation, but it must not
   silently submit a ticket. Ticket build/submit remains an explicit user
   action.

## Strategy/Dashboard Interaction

1. Strategy generates and validates the execution CSV plus report.
2. Strategy updates this contract and places a sample CSV for dashboard tests.
3. Dashboard consumes the sample first, then a published artifact under
   `structured_shadow_dir`.
4. Dashboard opens/block-comments the Kanban card if a required field is
   missing, ambiguous, or conflicts with existing API shape.
5. Strategy updates artifact/contract, then dashboard resumes.
