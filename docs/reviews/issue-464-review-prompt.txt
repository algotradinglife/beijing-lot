**Round 4** reviewed revision `fd2a823a` and returned needs-revision with one
blocker, and it was right. The `function-coverage-scan` added in round 3 proved
nothing: it searched bare names across test files, so unrelated occurrences of
`main` counted as coverage for the five entry scripts. Injecting
`AssertionError` into every `main()` still produced 165 passing tests and a
successful render. The gate certified a false conclusion.

Round 4's fix was to delete that gate rather than harden it:

1. 23 new tests **actually call** each entry script's `main()`: `--help`, missing
   mandatory arguments, out-of-range values (`--rate-per-minute`, `--limit`,
   `--batch-size`, `--workers`), an unknown `--play`, mutually exclusive roster
   modes, a missing authorization mode and an incompatible risk acknowledgment.
   Every path runs before the first HTTP request or database write, so none of
   it asserts the behaviour routed to #466-#474/#476.
2. The QMD gate now runs exactly that 23-case selection and asserts zero
   failures. Repeating the mutation yields `23 failed` and the **render exits
   1**; restoring it exits 0. The gate is falsifiable.
3. The coverage matrix gained a `main()` row and the document now states its
   evidence boundary: it does not claim a mechanical proof that every function
   repository-wide is covered.

**Round 5** reviewed revision `30933379` and returned needs-revision with one
blocker. It confirmed the round-3 fixes and the main-execution gate survive
mutation testing, but found ten functions still never executed by any test.
Three review rounds had raised the same class of problem, so the fix was to stop
judging coverage by name:

- `scripts/audit_execution_coverage.py` (new, reusable, pure helpers tested)
  injects an unconditional `raise AssertionError` as the first statement of
  **every** function in `src/titan_clean/` and the five entry scripts —
  private helpers and `main()`-local closures included — runs the acceptance
  command, and treats a still-passing suite as "no test reached this function".
  Every uncovered verdict is recomputed once and reported only when both runs
  agree, because single runs proved flaky.
- The QMD gate invokes it and asserts zero gaps. It is falsifiable: disabling
  one test's coverage makes the render exit 1.
- Dispositions: `_clean_cells` had no caller anywhere and was **deleted** as
  dead code rather than tested; `now_utc` (four scripts), `_fetch_aux` and
  `_capture_aux` gained tests; `needs_aux`, `reserve_n` and `worker` are
  `main()`-local closures with no importable name, so two end-to-end tests drive
  a full `main()` run against a temporary data root with transport and
  subprocess stubbed.

Round 5 also exposed a flaw in the round-5 test for `worker`: it runs on daemon
threads, so an injected exception kills the thread silently while `main()` still
prints `ALL_ISSUES_DONE`. That test now asserts the observable work (one
reservation per issue booked through `reserve_for_issue`) and fails under
mutation.

Audit result at the revision under review: **112 functions, 0 injection errors,
0 never executed**.

**Round 6** reviewed revision `2c2472e2` and returned needs-revision with four
in-scope blockers, all in this delivery's own gate and test code. Each was
reproduced before being fixed:

1. The auditor accepted an unattributable failure as proof of execution: an
   unrelated flaky test failing a run made a function count as covered from a
   single observation. Coverage now requires two consistent observations, and a
   `fail, fail` pair counts only when the probe's own exception marker appears
   in both outputs. `pass, fail` and `fail, pass` are inconclusive and fail the
   audit rather than defaulting to covered.
2. `--jobs > 1` ran probes concurrently over the same file. Reproduced: a
   `--jobs 4` run left probe exceptions in eleven source files, because one
   worker could read another's injected source as its "original" and write it
   back. Parallel execution is removed entirely; probes run strictly one at a
   time and the original bytes are restored on every path.
3. The QMD gate read only the summary line and ignored the auditor's exit
   status, so a failed audit whose summary still showed zero gaps rendered
   successfully. The gate now checks the exit status and the inconclusive count.
4. The round-5 end-to-end test pinned the incomplete-aux completion behaviour
   routed to #473: its stub wrote only the analysis capture while `needs_aux`
   inspects only that endpoint, so the run finished with handicap missing. The
   stub now persists both endpoints.

The gate is falsified two independent ways at the revision under review:
making the auditor report one inconclusive result exits 1, and disabling one
test's coverage to create four real gaps exits 1 — with no source-file
corruption in either case.

The delivery does **not** claim the routed behaviours are correct. That is a
deliberate, documented governance decision, not an oversight.
