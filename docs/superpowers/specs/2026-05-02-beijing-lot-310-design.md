# 北京单场 让球胜平负 (3/1/0) 量化策略 — 设计稿

**日期**: 2026-05-02
**作用域**: 北单 让球胜平负玩法的端到端量化系统（数据采集 → 概率模型 → EV/赔率/SP → 投注组合优化 → 回测 → 执行）

## 1. 目标与非目标

### 目标
- 在 N 场比赛构成的"批次"上获取**统计正期望**（长期 +EV）
- 控制**单批次最坏损失**（5% 分位 ROI 不低于约 −20%）
- 提供端到端可回测的系统，第一版上线时间 8–12 周

### 非目标（v1 不做）
- 北单其他玩法（上下单双、比分、半全场、总进球、胜负过关）
- 串关（all-or-nothing 结构与"控制最坏损失"目标冲突）
- 自建概率模型（Approach B）— v2 再考虑
- 全市场覆盖 — 第一阶段限五大联赛及主要欧赛事

## 2. 投注论 (Bet Thesis)

### 2.1 北单 SP 机制
- 彩池模型（parimutuel）：奖金 = SP × 2 × 0.65，其中 SP = 总投注 / 中奖票数
- 返奖率 65%，房费 35%
- 不是和庄家对赌，而是和其他购彩者对赌

### 2.2 Edge 来源（验证后确定）
**结构性 +EV 假设：北单 购彩者群体（中国散户）的投注分布偏离国际博彩市场（Pinnacle 等）的真实概率估计**。具体：

| 假设 | 方向 | 信心 | 来源 |
|---|---|---|---|
| 平局选项 SP 系统性偏高（散户回避平局） | "1" 选项 +EV | 高 | Forrest & Simmons; Deschamps & Gergaud |
| 主队/热门球队赢球 SP 偏低 | "3"（让后主胜，热门队） −EV | 中 | Fischer 2022 (COVID natural exp) |
| 极端冷门 SP 偏低（FLB 残留） | 极冷门 −EV | 中 | Snyder 1978; Hausch–Ziemba–Rubinstein 1981 |
| 小盘比赛 SP 噪声大 | 任意 ±10% 噪声 | 高 | 直觉 + 中文行业分析 |

**关键论断**：上述假设若不成立或不足以覆盖 35% 房费，**策略无 edge**。第一阶段必须用真实北单 SP 历史数据验证。

### 2.3 P_real（真实概率）来源
**Approach A**：从国际博彩市场反推。验证已完成（见 §6）：
- Pinnacle 1X2 校准良好（mean abs prob err < 2%）
- Pinnacle AH 校准良好（mean abs err < 1.5%）
- AH 边际成本 2.3%（北单 35% 房费的 1/15）

具体管道：Pinnacle AH（让球数 + 赔率）+ Pinnacle O/U 2.5 → Skellam 2 参数拟合 → 在北单整数让球数下读取 p3/p1/p0。技术细节见 `notebooks/ah_to_1x2.py` 与 `docs/research/ah-to-1x2-methodology.md`。

**校准误差**：英超 2024–25 上回测，模型重建 Pinnacle 自家 1X2 平均偏差 ~1.1pp（Brier 与原始书价无统计差异）。

**关键的整数线偏差（v2 必修）**：在 Big Five 5 季 8903 场实测（`notebooks/integer_line_test.py`）显示：
- 模型平均 **低估 p1（让球后平局）约 2.8pp**（实际 27.5% vs 预测 24.8%）
- 模型平均 **高估 p3（让后主胜）约 2.2pp**
- 模型 p0 校准良好

这是经典的 Dixon-Coles τ 效应（独立 Poisson 低估了低比分平局相关性）。后果严重：典型 SP_draw ≈ 3.4 下，每注 "1" 选项被低估 EV ≈ 0.028 × 3.4 × 0.65 ≈ **6.2%**。系统会**拒绝大量本应盈利的平局下注**。

**关键的 h-依赖性**：在 8903 场实测中，让球后平局的低估随 |h| 衰减：
- h = 0（56% 比赛）：p1 残差 = +3.5pp（最严重）
- |h| = 1（32% 比赛）：p1 残差 ≈ +2.0pp
- |h| ≥ 2（12% 比赛）：p1 残差 < 0.5pp（无需校正）

这与 Dixon-Coles τ 效应一致：低分差的平局（0-0, 1-1）相关性强；让球数大时平局变成"主队恰好赢 N 球"，τ 效应消失。

**v1 双轨方案**：
1. **h = 0 场次（多数）**：直接用 Pinnacle 1X2（去 vig 后），避开 Skellam 转换误差。无校正需要。
2. **h ≠ 0 场次**：用 Skellam AH→1X2，叠加分段校正：
```python
if abs(h) <= 1:
    p1 += 0.020; p3 -= 0.010; p0 -= 0.010
elif abs(h) == 0:  # 不会进入此分支（用 1X2 directly）
    pass
# else h>=2: no correction
# normalize so p3+p1+p0 = 1
```
**v2 升级**：拟合 Dixon-Coles τ 参数（用 Big Five 8903 场进球分布数据）替代分段校正。

## 4. 核心决策与依据

### 4.1 投注结构：单关，禁串关
**决定**：v1 仅单关，不下任何串关。
**依据**：串关方差呈乘性叠加（all-or-nothing 链），与"控制最坏损失"目标直接冲突。Monte Carlo（`portfolio_sim.py`）证实单关组合在 N=50 时 P5 ROI ≈ −22%；同等候选量串关 P5 远超 −80%。

### 4.2 候选选择：自下而上 EV 驱动
**决定**：不预设 3/1/0 比率配额；对每场每个选项独立计算 EV，EV ≥ 1.05 入选。
**依据**：用户首选自上而下（Approach A），但同意先用 EV 驱动（Approach B）跑通基线。Approach A 留作 v2 对比版本。

### 4.3 EV 阈值 T = 0.05（默认）— 与目标函数有关，需 Phase 4 σ_p 实测后再调
**决定**：v1 默认 T = 0.05。仅纳入 EV ≥ 1.05 的标的。

**依据**（`winners_curse.py` + `winners_curse_v2.py`，含 Kelly 加权与 log-growth 分析）：

合理操作点：σ_p ≈ 0.03（包含 Pinnacle 自身 σ ~0.025 + 我们的 AH→1X2 重建误差 ~0.011），群体偏差先验生效假设 edge_mean = +1% 至 +3%。

| T | 接受率 | realized true edge | mean Kelly stake | 每注 log growth |
|---|---|---|---|---|
| 0.00 | 53% | +2.6% | 1.9% | 5.1e-4 |
| 0.05 | 27% | +3.7% | 2.7% | 8.4e-4 |
| **0.10** | **10%** | **+4.6%** | **3.2%** | **11.3e-4** |
| 0.15 | 3% | +5.2% | 3.3% | 11.9e-4 (峰值) |
| 0.20 | <1% | +5.4% | 3.4% | 11.0e-4 (回落) |

**两个目标函数有不同最优解**：
- **目标 A — 最小化单批次最坏损失**（用户原始诉求）→ T = 0.05，搭配每周 N ≈ 50 候选 batch；批次 P5 ROI ~ −18%。
- **目标 B — 最大化长期 log-growth** → T = 0.10–0.15，每周 N ≈ 25 候选 batch；批次 P5 ROI ~ −25% 但平均增长更高。

**v1 默认采用 A（用户原诉求）**：T = 0.05。Phase 4 backtest 实测 σ_p 后再决定是否上调到 T = 0.10。

**重要警告（来自 stress 场景）**：当 σ_p ≥ 0.05 时，过高 T（≥ 0.18）会让 log-growth 转负——因为高 T 选出的多是 estimation noise 而非真 edge。**T 的安全上限是 0.15**。

### 4.4 仓位规则：1/4 Kelly + 三重上限
**决定**：
```
edge_i      = p_i × SP_i × 0.65 − 1
f_kelly_i   = edge_i / (SP_i × 0.65 − 1)
f_actual_i  = 0.25 × f_kelly_i
stake_i     = min(f_actual_i × bankroll, 0.05 × bankroll, 0.005 × pool_i)
```
**依据**：
- 1/4 Kelly：MacLean–Thorp–Ziemba (2010) 给出在 σ_p ≈ 0.015 + edge ≈ 5% 时的近似最优分数；半 Kelly 在 edge 估计噪声下方差过大。
- 5% bankroll 上限：保护单笔模型错误的总体伤害。
- 0.5% pool 上限：保证我们的下注不显著影响 SP，标准 Kelly 公式仍近似精确（自影响 ≪ 1%）。
- Kelly per-match 求和无需 portfolio 修正：独立比赛上 log-utility 可加（Smoczynski–Tomkins 2010, Whelan 2025）。

### 4.5 批次结构：N ≥ 50（多期聚合）
**决定**：批次 = 一周（或最少 50 个 EV ≥ 1.05 候选），不是单期。

**依据**（`portfolio_sim.py`）：

| N | edge=3% P5 ROI | edge=5% P5 ROI | edge=10% P5 ROI |
|---|---|---|---|
| 5 | −69% | −68% | −63% |
| 10 | −47% | −45% | −41% |
| 20 | −33% | −31% | −26% |
| **50** | **−20%** | **−18%** | **−13%** |
| 100 | −13% | −11% | −7% |

要满足"5% 分位 ROI ≥ −20%"，N ≥ 50。北单 一期 平均 5–10 场，全部 EV-pass 也不够；需多期聚合。**实操：每周末批次（含周中欧战）即可获 50–100 候选。**

### 4.6 总仓位上限：25% bankroll/批次
**决定**：批次内所有 stake 之和 ≤ 25% bankroll。超出按比例缩放。
**依据**：保护"系统性模型错误"风险（如所有比赛同一天，模型同向偏置导致全输）。

## 6. 风险与待验证项

### 6.1 数据风险（实测后已确定，2026-05-02）

**好消息：500.com 全量可爬。**
- URL 模板：`https://zx.500.com/zqdc/kaijiang.php?playid=1&expect=<ISSUE>`，纯 GB2312 HTML，无 JS、无验证码、无观察到的限流
- 历史期号约 **2,115 期**（自 2007-05），共约 **170k 场比赛** 可获取
- 备份源：cp.zgzcw.com（同样数据，AJAX endpoint）
- 估时：单脚本 ~80 LOC，~70 分钟跑完全量
- 详细爬虫规格见 `docs/research/data-sources-beidan.md`

**坏消息（影响回测设计）**：

1. **历史只保留中奖选项的 SP**。例如 阿森纳 -1 曼城 实际 1-1（让球后平），保留 SP_1 = 4.20，但 SP_3 与 SP_0 已被擦除。
2. **销量分布（每选项投注百分比）历史不留档**。`投注比例` 字段在已结算页面是 `--`。
3. **平均欧赔（1X2 主流博彩平均赔率）历史完整保留** — 这是个关键发现，可作为 Pinnacle/AH 的代理。
4. **赛前实时 3-SP + 销量比 是有的**（投注页 HTML 仍含 `<span class="tzbl">` 与 `<input class="spArr">`）。

### 6.1.1 后果：回测能做到什么程度

**可以做的（用历史数据）**：
- 计算我们模型在每场上的 p3/p1/p0
- 用历史平均欧赔反推"市场隐含概率"作为 truth proxy（缺乏 Pinnacle 历史时的回退方案）
- 对模型选定的下注（EV ≥ 1.05），检验：
  - 命中率 vs 模型预测
  - 中奖时实际 ROI（已知中奖侧 SP）
  - 不中时 ROI = −1（无需 SP）
- → **模型选择 + 实际 ROI 都可计算**。

**不可以做的**：
- 验证"群体偏差先验"（draw aversion / popularity bias）的实际方向与量级 — 需要销量比，历史无
- 模型信号的方差/分布建模（需要 3-SP 全向量，历史只有 1 个）
- 真实 SP 与平均欧赔的偏离规律建模（同上）

### 6.1.2 应对方案：双轨数据策略

**轨道 1（立即开始）：Live Collector**
- 启动一个常驻爬虫，poll 北单投注页（`cp.zgzcw.com/lottery/bdplayvsforJsp.action`）从期号公布到末场开赛前
- 5–15 分钟抓一次完整数据：3-SP（开盘到收盘）、销量比、让球数、参赛队
- 数据进我们自己的数据库
- **6–12 个月后**积累出真正可用于策略验证的历史数据集
- 工作量：~2 人天（agent 估算）

**轨道 2（短期可执行）：Limited Backtest with Proxies**
- 用历史 170k 场（500.com 已存）+ 历史平均欧赔，构建近似回测：
  - 假设北单 SP ≈ 0.65 / 平均欧赔的 fair odds（即假设北单等同分摊 + 35% 房费），作为 baseline
  - 把"真实北单 SP（中奖侧）"和"假设 SP"对比，**验证 baseline 偏差程度**
  - 在 baseline 上跑模型决策，估计模型选择的 hit rate 与平均 ROI
- 局限：无法量化群体偏差，**只能验证"模型 vs 平均欧赔"的预测准确性，不能验证"模型 vs 北单实际池"的 edge**
- 工作量：1 人周

**轨道 3（最稳妥）：Forward Test First**
- Live Collector 跑 3 个月后，开始小金额（500–2000 元）forward test
- 用真实 3-SP 数据 + 实际下注 → 6 个月后才有 200+ 注的统计意义样本
- 期间不下大注

**项目周期重新估计**：
- 原估 8–12 周到 v1 上线 → **改为 8–12 周到 Live Collector + Limited Backtest 完成；6–12 个月到全数据 Forward Test 验证；12–18 个月到 production scale**
- Phase 4 Go/No-Go 推迟约 6 个月（必须有真实 3-SP 与 销量 数据）

### 6.2 模型风险
- **群体偏差先验失效**：若 Phase 4 实证显示先验方向错误或绝对值远小于预期，整个 edge 来源不存在 → 项目终止
- **Pinnacle 赔率与北单 SP 在非五大联赛的覆盖度差异**：Pinnacle 对小联赛、非欧赛事流动性低，de-vig 后概率噪声大；那些场次需要替代源或剔除

### 6.3 操作风险
- 北单只在北京/天津/广东三地销售，若用户不在这三地，**实盘执行受限制**（需现场购买或代理）
- 体彩中心反馈延迟、对账错误等运营风险

### 6.4 监管 / 合规风险
- 中国大陆体彩为国家专营。本系统仅用于个人决策辅助，不做代购、不做盘口托管、不做收费咨询；输出只在用户本地保留。

### 6.5 必须实证回答的关键问题
1. **历史北单 SP 是否能稳定获取至少 1 年？** Phase 1 验证。
2. **群体偏差先验在北单的真实方向与量级是什么？** Phase 4 验证。
3. **σ_p（模型概率估计噪声）的真实大小？** Phase 4 验证；这决定 Kelly 系数是否需调整。
4. **每周批次中合格候选数（EV ≥ 1.05）是否稳定 ≥ 50？** Phase 3 回测确认；不达则放宽 T 或扩国家范围。
