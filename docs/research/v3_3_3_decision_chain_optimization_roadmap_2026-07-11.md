# v3.3.3 决策链优化路线图

日期：2026-07-11
状态：Active roadmap
正式基线：`active_v3.3.3`
观察对照：`v4.2`（不得提升为默认，不得作为运行时回退）

## 1. 目标与原则

本路线图围绕 `active_v3.3.3` 推进四阶段优化：先建立可信且可复现的决策基线，再提高主押质量、裁剪低价值保护，最后组合验证。正式版本不原地修改；实验以新的 shadow/candidate 版本发布，通过回放和前瞻验证后再决定是否升级。

优化目标分为三层：

1. 主押质量：主押命中率、概率校准、置信分层后的实际命中率。
2. 保护效率：保护挽救率、每个新增保护码的边际覆盖和边际收益。
3. 资金效率：平均覆盖深度、组合数乘数、固定预算可覆盖的独立比赛/票组数量、ROI 与回撤。

所有实验遵守以下约束：

- 只使用决策时点之前可见的数据；赛后生成 artifact 只能用于复盘，不能进入前瞻比较。
- 26071-26074 已被多次分析，只作为诊断集，不作为未见验证集。
- 历史回放使用滚动时间切分；最终晋级依赖后续新期的 paper-forward 样本。
- 主押、保护和资金分配分别评估，不允许用更深保护掩盖主押退化。
- 单选、双选、全包分别报告；全包不得只以覆盖率为依据晋级。

## 2. 统一指标合同

每个候选版本必须输出以下指标：

| 维度 | 指标 |
|---|---|
| 主押 | 主押命中率、Brier Score、置信分桶校准、主押 winning SP 分布 |
| 覆盖 | 押+保命中率、保护命中数、未覆盖赛果分布 |
| 深度 | 单/双/全数量、平均覆盖深度、额外保护码数量 |
| 保护效率 | 每个额外保护码的 rescue 数、rescue rate、边际 profit proxy |
| 资金效率 | 固定预算覆盖场数、票组数、组合数乘数、真实票组 ROI、最大回撤 |
| 稳定性 | 按期、联赛、让球档、情报完整度、概率差和 q/概率冲突分层 |

单腿 proxy 继续用于方向和保护的快速比较，但晋级结论必须同时通过固定预算的组合票回放。单腿 proxy 的成本定义为每个选择码一单位；组合票成本按各腿宽度乘法计算。

## 3. Phase 1：基线修复

### 3.1 目标

建立唯一、冻结、可复现的 `v3.3.3` 决策核心和结算口径。Phase 1 不改变策略参数，也不追求提高命中率。

### 3.2 任务清单

- [x] 提取共享的 v3.3.3 决策核心，定义稳定的 `DecisionInput -> DecisionOutput` 合同。
- [x] 让 API 快照物化和 structured artifact 生成调用同一核心，移除两套独立规则的漂移。
- [x] 添加逐场 parity/golden 测试：相同输入的主押、保护、停牌、版本和配置哈希必须一致。
- [x] 明确 `active_v3.3.3` 为唯一正式展示源；Active snapshot 只承担冻结/审计，不形成第二套用户可见建议。
- [x] 回放和 API 读取 artifact 时按开赛前锁定规则选择，不得简单按最新 mtime 选择赛后文件。
- [x] artifact 记录生成时间、输入快照时间、首场锁定时间和 `pre_kickoff_valid` 状态。
- [x] 修复无效结算字段：`total_stake=0` 时不得产生可解释为真实收益的 PnL/ROI。
- [x] 区分“比赛结算行”“单腿 proxy”“真实票池结算”，禁止字段混用。
- [x] 明确停牌语义：`stop` 若为不可出票则执行层选择必须为空；若仅为风险标签则改用独立字段。
- [x] 对部分赛后复盘标注 `reviewed/settled/total` 数量，不得冒充整期统计。
- [x] 为上述合同补充 API、artifact、settlement 和前端一致性测试。

### 3.3 产物

- 共享决策核心及输入/输出数据结构。
- v3.3.3 parity 测试集。
- artifact freeze selector 与时间有效性审计字段。
- 修正后的 settlement schema/响应。
- Phase 1 基线审计报告。

### 3.4 验收

- API 与 artifact 对同一输入的逐场决策 100% 一致。
- 所有正式历史比较只使用 `pre_kickoff_valid=true` 的 artifact。
- 不再出现零投注但有真实 PnL/ROI、部分复盘冒充整期等状态。
- 正式 v3.3.3 的列表、详情、结算和下注计划使用同一决策标识与选择集合。
- `py_compile`、后端目标测试、完整相关 pytest、前端测试和生产构建全部通过。

## 4. Phase 2：主押优化

### 4.1 目标

在不增加保护深度的前提下提高主押命中与置信校准，为后续资金权重提供更可靠的排序信号。

### 4.2 实验清单

- [x] `primary-reorder`：只在既有覆盖集合内重排主押，选择集合和成本完全不变。
- [x] `probability-first`：以校准后最高概率为主押，q/EV 主要用于资金权重和保护候选。
- [x] `draw-aware`：针对让球 `±1`、概率接近和让球平高发情形校准主押规则。
- [ ] 检验 handicap-fit、近期形态、市场漂移和情报文本是否真正提高样本外主押命中。
- [x] 对弱文本信号和规则关键词做消融实验，识别误翻转主押的来源。
- [x] 建立 A/B/C 主押等级，检验等级与实际命中、SP 和收益是否单调。

首轮结果见
[`v3_3_3_phase2_primary_optimization_2026-07-11.md`](v3_3_3_phase2_primary_optimization_2026-07-11.md)。
工程实验已完成，但策略验收未通过：开发段 probability-first 为 `+6.9pp`，后段验证为
`+0.0pp`，分层方向不稳定，A/B/C 也未形成单调命中。候选已作为
`execution_enabled=false` 的 artifact 诊断字段进入 forward 采样，正式 `active_v3.3.3` 不变。
Forward 的预注册边界、自动结算和晋级门槛见
[`v3_3_3_phase2_forward_protocol_2026-07-11.md`](v3_3_3_phase2_forward_protocol_2026-07-11.md)。
第二个预注册候选 `phase2_handicap_gated_probability_first/v0.2.0000` 只在平手盘和主队让 1
使用 probability-first，其他盘口保持基线；它与全局 v0.1 使用同一 forward 样本并行结算，
联赛标签仍只作诊断。

### 4.3 验收

- 样本外主押命中率相对基线提升至少 2 个百分点，且提升不集中于单一期次。
- 平均覆盖深度与组合成本不增加。
- 覆盖率下降不超过 1 个百分点。
- Brier Score、置信校准和固定预算 profit/ROI 不显著劣化。
- 至少一个候选在盘口、联赛和情报完整度分层中保持方向一致。

## 5. Phase 3：保护裁剪

### 5.1 目标

删除低边际价值的双选和全包，将保护从“自动扩展选择集合”改为可排序、可受预算约束的候选。

### 5.2 实验清单

- [ ] 为 q 分歧、概率第二名、让球平、handicap-fit、情报保护分别计算反事实边际价值。
- [ ] 统计每类保护的触发数、rescue 数、rescue rate、增量返还和组合成本。
- [ ] 建立保护候选结构：`code / reason / priority / marginal_cost / expected_rescue`。
- [ ] 默认只输出主押；满足边际价值阈值时才增加一个保护。
- [ ] 将全包决策移至票池/资金分配层，单场决策链只提供排序后的保护候选。
- [ ] 对“删除保护后损失覆盖”和“节省预算后新增分散票组收益”做成对回放。
- [ ] 对让球平保护单独分桶，防止整体裁剪重新暴露系统性平局漏判。

### 5.3 验收

- 平均覆盖深度至少下降 0.10，或固定预算可覆盖的独立比赛/票组提升至少 10%。
- 覆盖率下降不超过 1-2 个百分点。
- 每类保留保护都必须在样本外具有正的边际 profit proxy 或明确的回撤收益。
- 全包数量显著下降，且不能通过把全包迁移为无约束双选规避指标。
- 固定预算 ROI 和最大回撤不劣于基线的预设容忍区间。

## 6. Phase 4：组合实验

### 6.1 目标

识别收益究竟来自主押优化、保护裁剪还是两者交互，并形成可晋级的正式候选。

### 6.2 实验矩阵

| 候选 | 主押规则 | 保护规则 | 用途 |
|---|---|---|---|
| Baseline | v3.3.3 | v3.3.3 | 冻结对照 |
| Primary | Phase 2 最优 | v3.3.3 | 隔离主押贡献 |
| Lean cover | v3.3.3 | Phase 3 最优 | 隔离保护贡献 |
| Combined | Phase 2 最优 | Phase 3 最优 | 晋级候选 |

### 6.3 任务清单

- [ ] 使用相同决策时点、场次、预算、N、分段和随机种子进行组合票回放。
- [ ] 输出单腿 proxy、固定预算票组、分段收益、回撤和资金覆盖率。
- [ ] 使用滚动时间切分和按期 bootstrap 估计差异区间。
- [ ] 检查候选收益是否依赖少数高 SP 命中或单一期次。
- [ ] 保持 v4.2 为只读观察对照，不参与默认版本自动晋级。
- [ ] 将最佳候选作为 paper shadow 跟踪至少 5 期或 500 场。

### 6.4 晋级门槛

- 历史滚动验证至少覆盖 300 场；最终 paper-forward 至少 5 期或 500 场。
- 主押命中率相对基线提升至少 2 个百分点。
- 覆盖率下降不超过 1-2 个百分点。
- 平均深度下降至少 0.10，或固定预算分散能力提升至少 10%。
- profit proxy、真实票组 ROI、最大回撤和全损期数均不显著劣化。
- 改善不得由未来信息、赛后 artifact、单一期次或单个高 SP 票组驱动。

## 7. 时间顺序与依赖关系

```text
Phase 1 基线修复
  ├─ 唯一决策核心
  ├─ artifact 冻结与时间有效性
  ├─ 结算/复盘口径
  └─ parity 与前端一致性
          │
          ▼
Phase 2 主押优化 ─────────┐
                          ├─► Phase 4 组合实验 ─► paper-forward ─► 晋级评审
Phase 3 保护裁剪 ─────────┘
```

Phase 2 和 Phase 3 都依赖 Phase 1 的冻结基线。为减少变量混杂，执行顺序为 Phase 1 → Phase 2 → Phase 3 → Phase 4；Phase 2/3 的代码结构可以复用，但策略结论必须分别产出。任何阶段未通过验收时，正式 `active_v3.3.3` 保持不变。
