# N7/N5/N3 cooldown replay

Date: 2026-06-28

## Scope

Cooldown is tested as a capital layer after strategy selection. Tickets, legs,
and model decisions are unchanged. A cooldown rule only changes later issue
deployment after prior realized PnL.

All comparisons report:

- `roi_on_deployed_stake`: ROI only on money actually deployed.
- `roi_on_original_budget`: ROI using the original 512 units per issue
  denominator. This is the fairer number because skipped issues should not
  inflate ROI.

## Recommendation

Use this as the first cooldown rule:

`w5_n3_dynamic + full3_cool3_skip`

Rule:

1. Run the normal `w5_n3_dynamic` issue strategy.
2. If three deployed issues in a row are full-loss or near-full-loss, skip the
   next three issues.
3. Skipped issues do not update the cooldown trigger.
4. After three skipped issues, resume normal deployment.

Reason:

- It improves profit, original-budget ROI, and maxDD at the same time.
- It only skips 18 issues over the full 2014-2025 test, so it is a light-touch
  risk layer rather than a strategy replacement.
- The rule is interpretable: it reacts to actual dead-ticket clustering, not to
  model internals or future information.

Keep these as paper arms:

- `w5_n3_dynamic + full3_cool5_skip` for a stronger drawdown-control version.
- `balanced_w13 + dd10000_cool3_scale0p5` for a conservative half-stake risk
  mode.
- `high_ev_n7_512 + dd15000_cool3_skip` only as a research arm; the skip rate is
  high enough that it may be overfitted to historical drawdown clusters.
