## 0. 问题与机制

每场押**市场最热门**（最低 SP）。两条相互对抗的力：

- **抽水摊薄（有利）**：北单返还率 0.65 = 每**票**一次性抽 35%，**不分腿**。每腿盈亏平衡所需 `v=p×SP` 随 N 下降：`v* = 1.538^(1/N)`。
- **热门偏差（有利，稳定）**：实测热门腿 **realized v = p×SP = 1.122 > 1**（命中率 0.433 × 命中均结算 SP 2.589；n=1878）。散户高估冷门、低估热门。且热门往上漂（band 图 <3.5 +33%），按结算 SP 拿钱 = 顺风。
- **稀有事件方差（不利）**：全中概率 ~0.43^N 指数衰减，高 N 时中奖极稀有。

\* 精确全中概率 = 按期次池化 `ΣC(命中热门数, N) / ΣC(热门总数, N)`（组合数，无蒙特卡洛）。

- **独立上界**（假设腿独立、用稳定 v=1.122）随 N 升、约 **N=4 翻正**——抽水摊薄机制成立。
- **但期望中奖数随 N 塌缩**：N=7 仅 46、N=10 仅 **2.9**（每 2 万注）。中奖是**极稀有事件**。

## 2. 高 N 的真实限制：方差 / 不可测，不是相关性

脚本也打印一个 seeded 蒙特卡洛 ROI，但**它在 N≥6 处是噪声主导、不可作为点估计**：

> **重要教训（本次修订的起因）**：旧版脚本因 SQLite 无 `ORDER BY` + 未排序 issue/leg 顺序，**种子压不住非确定性**，同命令重复运行高 N ROI 在 +618% 与 −100% 间乱跳；旧文档据此写的「**N=5 +4.8% 甜区 / 第一个真实越过0的组合**」是一次随机抽样的偶然，**不成立，已删除**。现脚本完全确定性，但即便如此，N≥6 的 MC ROI 仍随「哪一两注稀有大奖落下」剧烈摆动（期望中奖数仅个位~几十），**本质不可测**。

**所以高 N 的限制不是「正相关砸碎」（我之前讲反了）**：各期热门命中率 q_j 在 0.36–0.56 之间（存在「整晚偏冷/偏热」的共同因子），这类期间异质属**轻微正相关**，对「全中」是**有利**的（正相关让一起中更易发生）。真正的限制是：

1. **方差/破产**：全中概率 0.43^N 指数衰减，要靠极少数暴富注实现 EV，方差巨大。
2. **不可测**：16 期、N≥7 时期望中奖数个位数 → 真实 ROI 在当前数据下**测不出来**（不是被证伪为负，是无法估计）。

## 3. 结论（诚实降级版）

1. **稳定成立**：热门 v=1.122>1；抽水每票一次 → 独立上界随 N 升、约 N=4 翻正。「低 SP 下提高 N」**方向有理**。
2. **但高 N 的真实 ROI 在 16 期数据上不可测**——独立上界为正≠实测为正；中奖太稀有、方差太大。**不能声称任何具体高 N 的盈利或「甜区」。**
3. **可测的只到 N≈4–5**（期望中奖数还有几百），那里独立上界刚翻正、值得 OOS 验证。
4. **真正要解决的是方差/可测性**，不是相关性。两个方向：
   - **累积更多 OOS 数据** → 已加 `FAV5` forward arm（`src/sp_drift/forward.py::favorite_arm_row`，每周累积，平注、不进 GATE-FT）。
   - **降方差的结构**：全包/包场（covered legs，必过、降方差，代价是资金 ×3^M + 税务封顶）——见 [[cost_rebate_tax_edge]] 与历史「包场族」（回测中唯一正 CAGR 的玩法族，待正式 OOS 验证）。

## 4. 局限

- 仅 16 期；高 N 的 MC ROI 不可测，**勿据此投真钱**。
- 用结算 winning_sp（已含热门有利漂移）；决策端能否锁定这些热门是落地问题。
- **税务封顶未建模**：热门串高 N 时组合 SP 大、票数多，易撞 1 万单票封顶 + 拆票，会再吃收益（[[cost_rebate_tax_edge]]）。
- 用「每场最热门」全集、未做选择；选 v 更高的子集或上述降方差结构应更稳。
