# v3.3.3 分段决策刷新与冻结协议

## 目标

在保留 26074 期 2026-07-10 23:27 整期 artifact 作为审计基准的前提下，允许未开赛分段使用最新赛前数据重走统一决策核心。刷新结果写入 SQLite Active 快照，不覆盖原 artifact。

## 分段与检查点

- 分段边界沿用正式 `by_segment` 下注计划，已经开赛的比赛不进入新建运营窗口。
- 每段在首场开赛前 `T-6h`、`T-2h`、`T-30m` 检查一次。
- `T-30m` 最终刷新完成后，在首场开赛前 25 分钟冻结该段；5 分钟间隔用于原子写入与失败重试。冻结后到达但未执行的检查点记为 `skipped_frozen`。
- 每次执行写入 `segment_decision_refresh_runs`，主键为期次、分段、检查点，保证幂等。
- Active 方向变化时自动确认新快照并将旧 Active 标为 superseded；无变化时只更新检查时间。

## 展示规则

- 期次看板显示每场 Active 决策快照生成时间。
- 下注设计仅显示当前运营段和下一段。
- 分段计划显示决策更新时间与冻结时间。
- 已开赛腿从当前段票组中剔除；剩余票组按最新 Active 方向重算腿宽和基础成本。
- 远于下一段的票组不展示，也不提前设计。

## 分段票组重新优化

- 每个成功的决策 checkpoint 后，导出当时全部 Active 快照到独立 structured artifact。
- 优化器通过 `operational_segment_windows_v1` 接收显式分段边界，禁止重新合并或重编号运营分段。
- 优化器使用 `active_selection_codes`，与期次看板展示方向保持同源；不使用另行重算的 shadow 方向替代 Active。
- 只优化尚未到达各自冻结时间的窗口；已经冻结或开赛的分段不被后续 checkpoint 改写。
- 新计划写入独立目录并标记 `operational_segment_plan=true`、checkpoint、生成时间和窗口冻结时间。API 在整期锁定后只允许这种逐段预锁产物，并优先选择最新版本。
- 生成失败时不发布 summary，API 继续使用上一份成功计划。

## 每票 N 上限

- 下注设计提供“每票 N 上限”：自动方案沿用决策链推荐的 N；用户只能选择低于自动 N 的上限，避免以交互方式提高串关长度。
- 每个成功检查点在自动方案之外生成可选 N 上限的独立、可审计产物。API 只返回与请求上限完全匹配的产物，不能用其他 N 的票组替代。
- N 上限约束单张票的场次数；总风险仍由分段预算控制。在“预算放大”模式下，较低 N 可能产生更多小票并接近预算，因此选择较低 N 时应同步下调预算。
- “基础投入”复用同一份已审计票组，将每组倍数固定为 1；不要求另行生成 `unit_once` artifact，也不重新优化方向或 N。
- 手动冻结会锁定当时所选 N 上限对应的计划 ID 和决策快照；后续自动检查点不得改写该段。

## 情报缺失单选约束

- 决策情报 TTL 为 120 分钟；采集层将情报标记为 `fresh`、`stale` 或 `missing`。
- 当情报缺失或过期且原始决策只有一个方向时，禁止直接形成单选。
- 概率次高方向同时满足概率不低于 24%、q 不低于 0.60 时，补为双选保护。
- 没有合格保护方向时清空执行选码并停牌，不用低依据方向强行扩选。
- 使用 #1-#36 的冻结输入回放原 8 场单选：7 场扩为双选、1 场停牌、剩余单选 0；覆盖由 2/8 提升到 5/8。该结果只验证约束行为，不作为独立策略收益晋级证据。

## 验收

### 检查点 SLA 与自动验收

- T2/T30 计划时间后 10 分钟仍未成功，Operations 写入 `segment_checkpoint_sla_overdue`；运行明确失败或因冻结跳过时立即告警。
- 每个成功检查点必须找到同一 `s<segment>-<checkpoint>` 的 operational summary，禁止用其他时间点产物代替。
- 自动验收四项：structured/SP 与 Phase 3 exact 字段完整；Phase 3 全部只读且正式选择未变；`max_selected_bundles=20` 且每段不超过 20 组；当前 summary 已进入 operational audit ledger。
- 状态写入 `results/segment_decision_forward_artifacts/<issue>/checkpoint_health.json`，每轮 artifact refresh 更新。
- 摘要缺失、超过 15 分钟未更新、SLA 超时或验收失败，均进入“运行状态”待处理事项，分类为“分段刷新”。
