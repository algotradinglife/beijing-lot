2. 策略演化

v1.0 — 单关 + EV 过滤 + 1/4 Kelly（最初设计）

超过 设定：每注 EV ≥ 1.05 入投注组合；每周聚合 N ≥ 50 候选；目标控制最坏损失 P5 ROI ≥ −20%

问题：35% 房费太高，单关 EV 永远负

v1.1 — 加入站点佣金（部分缓解）

自买票 + 7% 佣金返佣 → 净房费降到 28%。仍负 EV，仅"亏得少"。

▼

v2.0 — 7 关组合 + 站点 + 拆票避税（当前）

活跃 用户透露真实赚钱模式：组合稀释 rake + 站点佣金 + 拆票避免 20% 税

突破：35% 房费在 7 关组合下只收一次，per-leg break-even edge 从 53.8% 降到 6.4%。可达。

3. 核心数学：为什么 7 关是甜蜜点

3.1 北单 串关公式

奖金 (per 2 元票) = ∏ SP_i × 2 × 0.65

关键：0.65 只乘一次 — 35% 房费不论几关只收一次。

3.2 N 关 break-even per-leg edge

每腿需要 r ≥ (1/0.65)^(1/N) = 1.538^(1/N)
关数 N每腿需 r需要的概率 edge可行性
1（单关）1.53853.8%不可能
3 关1.15515.5%极困难
5 关1.0909.0%困难
7 关1.0646.4%可行（接近文献预测）
10 关1.0444.4%易但变量太大
15 关1.0292.9%易但中奖率 0.001%

3.3 加入佣金 + 拆票避税后的合并 EV

Net EV = (1+ε)^7 × 0.65 × τ + 0.07s − 1

τ = 1.0（拆票避税）；s = 持股比例（佣金分成）；ε = per-leg edge

per-leg ε无佣金无拆票仅拆票仅佣金拆票+全佣金
3%−43%−28%−36%−13%
5%−35%−22%−28%−1.5%
6%−32%−18%−25%+5.0%
7%−27%−13%−20%+11.3%
8%−24%−7%−17%+18.5%

盈利门槛：每腿 ε ≥ 5–6%（拆票 + 全佣金条件下）

关键发现：销量比可从 3-SP 直接推导

北单 parimutuel 公式蕴含恒等式 Σ(1/SP_i) = 1。即 share_i = 1 / SP_i。

实证：1,104 个 Live Collector snapshot 上，平均 Σ(1/SP) = 1.0026（标准差 0.002，最大偏差 1%）。100% 行落在 [0.99, 1.01] 区间。

意味着：不需要单独抓取销量比；不需要花钱买历史数据；Live Collector 已隐式获得。

7. 回测结果

7.1 单关回测（B2 agent）

数据：38,463 历史 北单 比赛 / 6,228 EV-pass picks（empirical OLS proxy SP）

累计 ROI：−35.43% （95% bootstrap CI [−37.62%, −33.36%]）

按选项分组：3 / 1 / 0 全部 ROI ≈ −35%，无一显著

按让球数分组：h=0 / |h|=1 / |h|≥2 全部 ROI ≈ −35%，无一显著

按 EV 桶分组：5 个桶全部 ROI 在 −34% ~ −37%，模型预测 EV 不能预测实际 ROI

结论：符合零信号 当 proxy SP 来自同源 avg_eu 市场，模型无法找到 edge。

7.2 组合回测（half-backtest）

数据：150 期 / 44 活跃周 / 1,831 TicketPlan / 345,306 物理票 / 759,032 元总仓

中奖组合数：0 / 1,831

中奖周数：0 / 44

累计 ROI：−100.00% （95% CI [−100, −100]）

模型预测平均 joint_p：~11%（应有 ~204 中奖）

实际命中：0 — 不仅未校准，是反向的 winner's curse 引擎

⚠ Winner's Curse 引擎机制（重要诊断）

edge ≥ 0.05 过滤器选中的腿，恰好是 OLS proxy-SP 残差 + de-vig 噪声同向偏移最大的腿——也就是模型最可能错的腿。把 7 条带选择偏差的腿乘起来，joint probability 指数级崩塌。

组合 ROI 比单关更差 64.57pp，因为 7 关结构放大了同源数据的偏差。

8. 组合优化器

v1 实现于 src/combo_optimizer/。36/36 单元测试通过。

8.1 算法

  1. 过滤候选 edge ≥ 0.05 + 同场去重（同 match 取 EV 最高的选项）
  2. 取 top K（默认 14）by EV
  3. 枚举 C(K, 7) = 3,432 个组合
  4. 过滤组合 EV ≥ 0.10
  5. 每个组合：1/4 Kelly 仓位 → 拆票（每票奖金 ≤ 9999） → 偶数元 stake → 总仓 ≤ 25% bankroll

10. 三个决定性洞察

10.1 销量比 ≡ 1 / SP_i（解决核心数据缺口）

北单 parimutuel 公式蕴含 Σ(1/SP_i) = 1。Live Collector 抓取 3-SP 即得销量比。不需要花钱买数据，不需要登录态，不需要找其他端点。

10.2 Dixon-Coles τ 在整数线上的偏差（v1 必修）

Skellam 模型在 h=0 时低估平局 3.5pp。每注 "1" 选项 EV 被低估 ~6.2%，会拒绝大量本应盈利的下注。已设计分段校正方案。

10.3 同源数据触发 Winner's Curse（架构验证）

组合回测 ROI = −100% 证实：用 avg_eu 同时估 p 和 SP，过滤器会选中"模型最可能错"的腿。必须用独立数据源（Pinnacle 算 p / 北单实测 SP），这正是 v1/v2 架构选择。
